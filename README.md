# Протокол

Приложение для Windows x64 записывает встречу на компьютере сотрудника. Комната и звонок сохраняются в отдельных WAV. Сервер принимает завершённую встречу, строит расшифровку, определяет говорящих и составляет конспект. Совещание записывается локально и переживает отключение сети.

**Сотруднику:** скачайте ProtocolSetup.msi с главной страницы корпоративного сервера, установите и откройте Protocol через меню Пуск. Подключите гарнитуру до начала записи. Сохраните подключение в приложении, нажмите «Начать запись», а в конце «Завершить и отправить». Оставьте приложение открытым до подтверждения сервером. Для звонка используйте устройства связи Windows по умолчанию. Произвольный отдельный выход, назначенный только внутри приложения звонка, клиент не определяет.

**Голоса:** режим образца записывает только микрофон. Распознанное имя зависит от качества зарегистрированного образца. Две аудиодорожки — это комната и звонок, а не два человека.

**Данные:** файлы встреч находятся в %LOCALAPPDATA%\Protocol\Recordings, образцы в VoiceSamples рядом. Серверная очередь, образцы и результаты не входят в исходники.

## Сборка Windows-клиента

В outputs/protocol-recorder поместите чистый переносимый CPython 3.12 x64 в audio-runtime (python.exe, pythonw.exe, DLLs, Lib, tcl и DLL из корня установки). Нужны tkinter и msilib. Установите двоичный пакет PyAudioWPatch==0.2.12.9 в audio-packages с помощью pip --target в чистом Python 3.12 x64. Сборка использует csc.exe из Windows .NET Framework 4.x и WinMetadata из Windows 10/11. Скрипт сборки рассчитан на PowerShell 7.

Запустите build-desktop.ps1 с параметром -SigningKey и абсолютным путём к закрытому файлу ключа вне репозитория. При первом выпуске скрипт создаёт ключ, защищённый Windows DPAPI. Для выпуска обновлений требуются тот же ключ и тот же профиль Windows. Сохраняйте его отдельно и не заменяйте между релизами. Новый ключ не будет принят старыми клиентами. Обновляйте номер версии клиента, MSI и подписанного манифеста согласованно.

Сборка создаёт ProtocolSetup.msi и Protocol-0.10.0.zip в outputs/local-meeting-ai/dist. После проверки MSI через verify_msi.py скопируйте ZIP в MeetingAI-Client-Windows.zip рядом. Сервер раздаёт MSI для первой установки и ZIP с подписанным манифестом для кнопки «Проверить обновление». Код не выполняет присланные сервером команды.

## Сервер

Исходники и список Python-зависимостей находятся в outputs/local-meeting-ai. Веса и исполняемый файл llama.cpp не входят в Git: их расположение задаёт config.json. Скрипты запуска в этом снимке рассчитаны на уже подготовленное серверное окружение. Для чистого ПК сначала нужны отдельные локальные модели и зависимости. Настройки доступа и данные существующего сервера переносить в Git не следует.

## Границы проверки

Проверены системный звук, получение аудиокадров через Windows AudioGraph на тестовом источнике, содержимое MSI, подпись обновлений и выдача файлов сервером. Полная установка и запись физического микрофона вместе со звонком на машине сотрудника требуют приёмки.
