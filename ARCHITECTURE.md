# Структура и обслуживание

## Рабочий путь

- `web/index.html`, `app.js`, `queue-ui.js`, `lifecycle-ui.js`: список встреч, очередь и результаты.
- `web/recording-ui.js`: встраивание записи и управление голосовыми профилями.
- `web/browser.html`, `browser.js`: разрешения устройств, MediaRecorder, IndexedDB и отправка. При скрытии окна запись остаётся смонтированной.
- `web/theme.js`: общий переключатель темы и синхронизация с окном записи.
- `web_server.py`, `browser_tls.py`, `network_access.py`: маршруты, HTTP/HTTPS и доступ.
- `browser_meeting.py`, `meeting_session.py`: приём дорожек, проверка архива, отдельная обработка источников и объединение результата.
- `meeting_ai.py`, `folder_watch.py`, `record_lifecycle.py`: очередь SQLite, импорт, атомарное сохранение, корзина и восстановление.
- `audio_io.py`, `long_audio.py`, `session_audio.py`: декодирование на диск, обработка окнами, WAV/RF64.
- `speakers.py`: сегментация, признаки голоса, регистрация и осторожное присвоение имени.
- `summary_pipeline.py`: конспектирование частями с контрольными точками.
- `open_app.py`, `boot_server.py`, скрипты запуска: запуск сервера вручную и через Windows Task Scheduler.

## Совместимость

Старые Windows-клиенты и звуковые адаптеры не удалены. Сервер всё ещё импортирует Recorder и связанные модули; механическое удаление этих файлов нарушит запуск. Их выделение в отдельный пакет должно быть отдельным изменением с проверкой маршрутов и старых загрузок. Основной пользовательский путь — браузер.

Модели, записи, профили, настройки доступа, ключи, резервные копии и результаты не относятся к исходникам. Их нельзя удалять как «мусор». Git хранит исходники; резервное копирование данных выполняется отдельно.

## Проверка перед выпуском

Из корня репозитория с установленными серверными зависимостями:

```
python -m unittest discover -s tests -p "test_*.py"
python outputs/local-meeting-ai/test_speakers.py
node --check outputs/local-meeting-ai/web/browser.js
node --check outputs/local-meeting-ai/web/recording-ui.js
```

Тесты создают искусственные записи в исключённых из Git каталогах tests/*-tests. Не используют записи сотрудников. Тесты конспектирования проверяют управление частями с подставным ответом модели, а не качество реальной нейросети.

Приёмка на устройстве: начать запись комнаты и звонка, проверить оба индикатора, вернуться к списку и открыть запись повторно, завершить, дождаться подтверждения сервером, проверить результат. Автоматические тесты не заменяют проверку разрешений и звуковых устройств браузера.
